# 空调温控 App 宪法 — v2.2.0 改进

## 核心原则

### I. 数据持久化安全 (NON-NEGOTIABLE)
禁止在任何生命周期钩子 (`onHide`、`onUnload` 等) 中调用 `uni.clearStorageSync()` 或批量删除 storage。
用户数据（连接信息、STA 记忆、设备配置）必须持久保存，除非用户主动执行「断开」或「重置」操作。
**理由**：切后台清空 storage 会导致用户每次返回 App 都断连，是灾难级用户体验缺陷。

### II. Vue 响应式规范 (NON-NEGOTIABLE)
所有在模板中绑定的数据字段（`v-model`、`v-if`、`{{ }}` 等）**必须**在 `data()` 中声明初始值。
禁止赋值给未声明的数据字段，否则 Vue2 无法追踪变化。
**理由**：未声明的响应式字段是 Vue2 最隐蔽的 Bug 来源，条件判断可能永久失效。

### III. 防抖与竞态保护
所有用户触发型异步操作（连接设备、开关空调、切换场景、表单提交）必须实现以下防护：
- 操作进行中禁用触发按钮（`:disabled` 或 `pointer-events: none`）
- 连续的快速点击只执行最后一次
- 竞态条件下防止回调覆盖标志位
**理由**：`toggleACStatus`、`switchScene`、`doConnect` 等高频操作在无防抖时会产生重复请求，服务端状态与实际不符。

### IV. 代码去重（DRY 原则）
相同逻辑不得在多个页面中复制粘贴。以下场景必须抽取为 mixin 或全局方法：
- `checkDevice()` — 当前在 12 个页面重复
- `showToast`/`showConfirm` — 在 13 个页面重复
- `apiService.setDeviceAddress()` 调用链
**理由**：复制粘贴的代码在修改时容易遗漏，导致页面间行为不一致。

### V. 统一错误处理与用户反馈
所有异步操作必须有一个**统一的错误处理通道**：
- 每个 HTTP/WebSocket 请求的 `catch` 分支必须向用户展示可读的错误信息
- 设备离线必须**及时检测**（心跳或轮询），而不是等到用户操作后才报错
- 错误信息必须中文友好，不暴露技术细节
**理由**：当前错误处理不统一，有些静默丢失，有些抛技术细节，用户无法判断是网络问题还是设备问题。

## 技术约束

| 约束 | 说明 |
|------|------|
| 语言 | JavaScript (Vue2) — 不加 TypeScript，不加其他构建工具 |
| 状态管理 | 优先抽取 mixin 而非引入 Vuex/Pinia（减少改动量） |
| UI 风格 | Ant Design 蓝 #1677FF + 圆角卡片，保持现有设计体系 |
| 兼容性 | uni-app HBuilderX 构建，支持 Android/iOS/H5 |
| Git | 每次改动提交一个独立 commit，message 格式 `fix:` / `refactor:` / `chore:` |

## 开发工作流

1. **问题 → Constitution**: 每个改进必须回归到宪法原则，确保不产生新问题
2. **修复顺序**: 严重 (Critical) → 主要 (Major) → 次要 (Minor)
3. **验收标准**: 每次修复后检查 (a) 原有功能不被破坏 (b) 修复目标达成
4. **代码审查**: 避免在修复中引入新的重复代码

## 治理

本宪法自批准之日起生效。所有后续开发和修改必须遵守以上原则。
对宪法原则的修改需要记录在案并提交独立 commit。
违反原则的代码将被 marked 为技术债务。
