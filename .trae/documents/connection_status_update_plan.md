# 设备连接状态更新与按钮反馈实现计划

## 任务分解与优先级

### [x] 任务 1: 实现页面间设备连接状态实时同步
- **优先级**: P0
- **依赖**: 无
- **描述**:
  - 实现设备管理页面与首页之间的连接状态实时同步
  - 当在设备管理页面连接或断开设备时，首页能立即更新状态
  - 使用事件总线或全局状态管理实现页面间通信
- **成功标准**:
  - 在设备管理页面连接/断开设备后，首页状态立即更新
  - 不需要等待定时器检查就能看到状态变化
- **测试要求**:
  - `programmatic` TR-1.1: 在设备管理页面连接设备后，首页状态应在1秒内更新
  - `human-judgement` TR-1.2: 操作后首页状态变化明显，无延迟感
- **备注**: 考虑使用uni-app的事件总线或Vuex进行状态管理

- **优先级**: P1
- **依赖**: 任务 1

- **成功标准**:

  - 定时检查机制能作为实时同步的备份
- **测试要求**:

- **备注**: 保持现有的10秒检查间隔，但确保页面切换时立即检查

## 实现策略

1. **页面间通信**:
   - 使用uni-app的事件总线机制，在设备连接状态变化时发送事件
   - 首页监听事件并更新状态

2. **按钮反馈**:
   - 为每个保存按钮添加加载状态变量
   - 使用统一的Loading组件显示加载状态
   - 使用uni.showToast显示操作结果
   - 根据设备连接状态动态禁用按钮

3. **代码复用**:
   - 提取通用的按钮反馈逻辑到组件或混入
   - 确保所有设置页面使用相同的反馈机制

4. **性能优化**:
   - 减少不必要的API调用
   - 优化状态检查逻辑
   - 确保实时同步不影响应用性能

## 预期成果

- 首页设备连接状态实时更新，无延迟
- 所有设置页面的保存按钮有完善的状态反馈
- 设备未连接时所有提交按钮自动禁用
- 保持统一的用户体验和视觉风格
